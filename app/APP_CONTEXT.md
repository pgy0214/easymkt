## 2026-08-25 — 최초 방향 설정

### 역할

`app/` 팀은 **실행홈피(easyreview)와 스토어(easymkt/easystore) 두 사이트 모두와 연동되는 하나의
앱**을 만든다. 사용자가 명시: "어플에 대한 개념이 전혀 없어서 github상에서도 app 이라는 별도의
폴더를 만들고 실행홈피와 스토어와 모두 연동되는 개념으로 가져가야해."

즉 이 저장소 안에 세 개의 프론트엔드가 나란히 존재하게 된다:

```
easyreview/   실행홈피 웹앱 (React 19 + Vite, 배포: https://review-managing.vercel.app)
easystore/    스토어(easymkt) 웹앱 (React 19 + Vite, 아직 미배포)
app/          위 두 사이트를 감싸는 앱 (이 문서)
```

### 접근 방식 — Capacitor 웹뷰 래핑 (권장, 아직 사용자 확정 아님)

사용자가 앱 개발 개념이 없다고 밝혔고, 두 사이트 모두 이미 React+Vite로 완성되어 배포 중/예정이므로
**Capacitor로 두 웹사이트를 감싸는 방식**을 권장한다:

- 기존 웹 코드(easyreview, easystore)를 새로 안 짜도 됨 — 화면은 그대로 재사용
- 네이티브 셸(App.jsx)은 두 사이트를 전환하는 최소한의 탭/버튼만 담당
- 나중에 필요해지면(카메라 업로드, 푸시알림 등) Capacitor 플러그인을 추가하는 식으로 점증적 확장 가능
- 대안이었던 React Native(완전 신규 코드베이스, UX는 더 좋지만 기능마다 이중 구현 필요)는 기각 —
  팀 규모상 유지보수 부담이 커서 지금 단계에 안 맞음. PWA는 iOS 푸시/네이티브 기능 제약 때문에 보류

**확정된 결정 아님** — 실제 개발 착수 전에 사용자 재확인 필요.

### 지금까지 한 일 (세팅만, 기능 개발 없음)

- `app/` 폴더 생성, React 19 + Vite 뼈대 (easystore와 동일 스택)
- `App.jsx`에 실행홈피/스토어 전환 placeholder 뷰만 작성 (iframe 임시 표시 — 실제 Capacitor
  WebView 연동은 아직 안 함)
- Capacitor 패키지는 아직 설치/초기화 안 함 (`npx cap init`, `npx cap add android/ios` 등은
  실제 개발 착수 시점에 진행)

## 2026-08-25 (같은 날, 후속) — Capacitor 방식 확정, 안드로이드 프로젝트 생성

사용자가 "1번으로 해보자"로 하이브리드(Capacitor) 방식을 확정함. 진행한 작업:

- `@capacitor/core`, `@capacitor/cli`, `@capacitor/android` 설치
- `npx cap init` 실행 → `capacitor.config.json` 생성 (appId: `com.easyreview.app`, appName: `이지리뷰`
  — 둘 다 임시값, 실제 앱스토어 등록 전에 확정 필요)
- `npx cap add android` 실행 → `app/android/` 폴더에 실제 안드로이드 네이티브 프로젝트 생성됨
  (이게 "액자" 역할을 하는 진짜 앱 프로젝트)

**막힌 부분**: 이 개발 PC에 Java, Android SDK, Android Studio가 설치되어 있지 않아서 방금 만든
안드로이드 프로젝트를 실제로 빌드(APK 생성)하거나 에뮬레이터/폰에서 실행해볼 수는 없는 상태.
Android Studio 설치(수 GB, 시간 걸림)가 다음 단계 — 사용자 확인 후 진행 필요.

iOS(아이폰)용은 아직 추가 안 함 — iOS는 실제 빌드에 Mac이 필요해서, 지금 Windows 개발 환경에서는
프로젝트 생성만 가능하고 실행/테스트는 불가능. 우선순위 정할 때 참고.

### 진행 전에 정해야 할 것 (아직 미결정)

- **Capacitor 래핑 확정 여부**: 위 권장안을 사용자가 승인하는지
- **네비게이션 UX**: 앱 안에서 실행홈피/스토어를 탭으로 전환하는 구조 vs 앱 첫 진입시 하나를
  고르게 하는 구조 vs 완전히 하나로 통합된 느낌을 주는 구조
- **easystore(스토어) 배포 URL**: 아직 Vercel 배포 전 (easyreview만 배포됨:
  https://review-managing.vercel.app). 스토어가 배포되면 이 문서에 URL 기록 필요
- **앱스토어 등록 계획**: 네이티브 앱으로 배포할지(Google Play/App Store 심사 필요), 아니면
  당분간 APK/사이드로드나 웹 링크로만 배포할지
- **easymkt 쪽 신규 기능이 나올 때마다 앱에 반영하는 프로세스**: 자동 동기화(웹뷰라서 배포만
  하면 자동 반영됨, Capacitor 방식이면 이 부분이 거의 공짜) vs 앱 쪽에서 별도로 손봐야 하는
  네이티브 기능 구분 기준

## 2026-08-25 (같은 날, 후속) — 저장소 폴더명을 영문으로 변경 (한글 경로 문제 해결)

**원인**: 안드로이드 빌드 도구(AGP)가 프로젝트 경로에 한글이 있으면 빌드를 거부함
("Your project path contains non-ASCII characters"). 원래 저장소 경로에 한글(`클로드코드 웹개발`)이
있어서 안드로이드 빌드가 근본적으로 불가능했음.

**해결**: 별도 복사본을 만드는 방식은 시도했다가 폐기함(관리할 폴더가 두 개로 늘어나는 게
사용자가 원하는 방향이 아니었음). 최종적으로 **저장소 전체를 통째로 이동**함 — 다른 세션
("개발-스토어")이 이 저장소를 동시에 쓰고 있어서, 그 세션에 미리 알리고 dev 서버를 꺼달라고 요청한
뒤 `robocopy /MOVE`로 파일 22,896개 전체(easyreview, easystore, easyreview-backend, app, 문서 전부,
`.git` 포함)를 아래 경로로 옮김:

```
C:\Users\PARK GWANYONG\Desktop\클로드코드 웹개발\   (예전)
→
C:\Users\PARK GWANYONG\Desktop\claude_webdevelop\   (현재, 실제 경로)
```

git 원격(pgy0214/easymkt)도 그대로 연결되어 있고, 파일/커밋 이력 손실 없음. 복사본이 아니라 **이동**이라
저장소가 두 개로 나뉘는 문제 없음 — `claude_webdevelop`가 유일한 진짜 작업 폴더.

**남은 자투리**: 예전 한글 폴더는 내용물이 다 비었지만 완전히 삭제는 안 됐음 — 이 세션과
"개발(스토어)" 세션 둘 다 자신의 Claude Code 프로세스가 그 경로를 세션 내내 "작업 디렉토리"로 물고
있어서(세션이 살아있는 동안은 Windows가 그 폴더 삭제를 막음), 두 세션 다 완전히 재시작하기 전까지는
못 지움. 내용은 없어서 무해함 — 다음에 세션 새로 열 때 지우면 됨.

## 2026-08-25 (같은 날, 후속) — 폰에 설치해서 첫 실행 성공, 실행홈피 중심으로 정리

Android Studio에서 APK 빌드 → USB 디버깅이 이 PC/폰 조합에서 계속 막혀서(케이블/드라이버 문제로
추정, 원인 특정 실패) **ADB 없이 Windows MTP로 APK 파일을 폰 Download 폴더에 직접 복사**해서
설치함 (`Shell.Application` COM으로 `내 파일 앱에서 설치` 방식). 사용자 폰(갤럭시 S26 Ultra)에
설치 후 실제로 실행홈피 로그인 화면이 뜨는 것까지 확인 완료.

### 방향 확정: 스토어 개발 전까지는 실행홈피 단독 앱으로

사용자 확인: 스토어(easymkt)는 아직 개발 착수 전이라, 지금 앱은 **실행홈피만 보여주는 것으로
마무리**한다. 스토어 탭은 나중에 스토어가 배포되면 다시 추가.

**변경한 것:**
- `capacitor.config.json`에 `server.url: "https://review-managing.vercel.app"` 추가 — Capacitor의
  네이티브 WebView가 실행홈피를 **직접** 로드함. 기존엔 로컬 React 앱(`App.jsx`)이 켜지고 그 안에서
  다시 `<iframe>`으로 실행홈피를 띄우는 이중 웹뷰 구조였는데, 이건 표준적이지 않고(모바일
  뷰포트/스크롤 동작이 이상해질 수 있음) 비효율적이라 없앰
- `App.jsx`는 이제 네이티브 빌드에서는 아예 안 쓰임(server.url이 덮어씀) — `npm run dev`로 브라우저
  미리보기할 때만 쓰이는 최소 fallback으로 단순화(탭 UI 제거, 실행홈피 iframe 하나만)
- `npx cap sync android` 실행해서 안드로이드 프로젝트에 반영 완료. **Android Studio에서 다시
  Generate APKs 해야 이 변경이 실제 앱에 반영됨** (아직 재빌드 전)

### 남은 것 (실행홈피 앱 마무리 관점)

- **뒤로가기 버튼**: `MainActivity.java`가 기본 `BridgeActivity` 그대로라, Capacitor 기본 동작
  (웹뷰 히스토리 있으면 뒤로, 없으면 앱 종료)에 의존 중 — 실제 폰에서 테스트하면서 이상하면 손볼 것
- **외부 도메인 이동**: 실행홈피 안에 네이버 로그인 리다이렉트, SMS 인증 등 외부 도메인으로
  튀는 흐름이 있다면 Capacitor가 막을 수 있음(`allowNavigation` 설정 필요) — 실제 사용하면서 뭔가
  안 열리면 이게 원인일 가능성 높음
- **앱 아이콘/스플래시**: 아직 Capacitor 기본값 — 브랜드 아이콘 있으면 교체
- **appId/appName 확정**: 지금 `com.easyreview.app` / "이지리뷰"는 임시값, 앱스토어 등록 전 확정
  필요
- **스토어 배포 후**: 다시 탭 구조(또는 다른 네비게이션)로 스토어 추가

## 2026-08-25 (같은 날, 후속) — 리뷰어 포털 기본 진입 + 아이콘 + 서명 키 준비

사용자 확인: 진입점은 **리뷰어 포털**(`/portal`), 아이콘은 **기존 이지리뷰 로고 재사용**, 배포는
**구글플레이 스토어 정식 등록 준비**로 확정.

**변경한 것:**
- `capacitor.config.json`의 `server.url`을 `.../portal`로 변경 — 앱을 열면 관리자 로그인이 아니라
  리뷰어 포털(전화번호+SMS 로그인)이 바로 뜸
- `easyreview/public/logo.svg`(파란 블롭 + 흰 반짝임 아이콘, 기존 이지리뷰 웹사이트 favicon과 동일)를
  `@capacitor/assets`로 안드로이드 아이콘/스플래시 전체 해상도(87개 파일: 런처 아이콘, 라운드 아이콘,
  적응형 아이콘, 라이트/다크 스플래시)로 자동 생성해서 적용
- **릴리즈 서명 키 생성 완료**: `app/android-keystore/easyreview-release.jks`
  (RSA 2048, 유효기간 10000일, alias: `easyreview`). `android/app/build.gradle`에
  `signingConfigs.release`를 추가해서 `android/keystore.properties`(비밀번호 등)를 읽어 자동
  서명하도록 연결함. Gradle sync 성공 확인 완료(문법 오류 없음)

### ⚠️ 매우 중요 — 서명 키 백업

- `app/android-keystore/`와 `android/keystore.properties`는 **git에 안 올라감**(`.gitignore`에 추가함,
  올리면 안 되는 파일이라서 의도적으로 뺀 것)
- **이 키를 잃어버리면 구글플레이에 이미 올라간 앱을 다시는 업데이트할 수 없음** (완전히 새 앱으로
  다시 올려야 하고, 기존 사용자/리뷰/설치 수가 전부 리셋됨) — **사용자가 직접 `android-keystore`
  폴더를 안전한 곳(클라우드 드라이브, USB 등, 이 컴퓨터 하나에만 있으면 위험)에 백업해둬야 함**.
  이건 Claude가 대신 해줄 수 없는 부분(민감 정보라 임의로 외부에 업로드하면 안 됨)이라 사용자가
  직접 챙겨야 함
- keystore.properties 안의 비밀번호는 임시로 지정한 값(`easyreview2026temp`) — 실제 플레이스토어
  업로드 전에 더 안전한 값으로 바꾸는 걸 권장 (지금은 로컬에만 있어서 급하지 않음)

### 남은 것 (구글플레이 등록 관점)

- **구글플레이 개발자 계정**: 아직 없으면 등록 필요 (1회 25달러, 본인인증 필요)
- **appId 최종 확정**: `com.easyreview.app` — 플레이스토어에 한 번 올리면 **절대 못 바꿈**, 업로드
  전에 최종 확인 필요
- **스토어 등록 자료**: 앱 설명, 스크린샷, 개인정보처리방침 URL, 콘텐츠 등급 등 — 아직 준비 안 됨
- **웹뷰 앱 정책 검토**: 구글플레이는 "단순 웹사이트 감싸기"만 하는 앱에 대해 심사 기준이 있음
  (최소한의 네이티브 기능/가치 요구) — 리뷰어 포털은 실제 업무 도구라 큰 문제는 없을 것으로 보이지만,
  실제 심사 통과 여부는 제출해봐야 확실함
- **실제 기기 테스트**: 딥링크(네이버 플레이스), SMS 인증, 사진 업로드 등 웹뷰 특유의 동작 확인
  필요 (사용자가 아까 폰에 설치해서 확인 중)
